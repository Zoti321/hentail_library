# Cross-feature collaboration

Follow ADR-0034/0039/0045/0050/0051. First check whether the consumer may reach the producer: cross-feature dependencies use owner public APIs, respect forbidden edges and keep the public graph acyclic. Shared/core cannot depend on features. `composition/` binds implementations and bridges dependencies.

## Public surfaces

`features/<owner>/public.dart` aggregates only the available capability surfaces:

- `public/contracts.dart`: pure Dart types, repository/IO contracts, Command/Query signatures and rules.
- `public/providers.dart`: observable state and Command/Query tokens.
- `public/widgets.dart`: pages, components and presentation helpers.

Public files contain exports only. Use an existing narrow export when a broad barrel would pull UI into inner code. Canonical presentation exports select symbols explicitly; provider surfaces export provider tokens. Factories and overrides stay in composition. `public/infrastructure/` is a dedicated adapter-to-adapter surface excluded from ordinary barrels.

## Capability shape

- **Command**: a typed function. `ref.read(commandProvider)(...)` executes at call time; constructing or rebuilding a provider performs no business write. Read the current Notifier inside the callback or bind a stable pure Dart use case.
- **Query**: a function for a one-time read. Preserve fresh reads and editing/session snapshots; do not replace them with an indefinitely cached FutureProvider.
- **Continuous state**: owner StreamProvider/state Provider, consumed with `watch/select`. Preserve initial loading, data, errors, subsequent changes and cancellation.
- **Committed fact**: a DomainEvent, published from application/infrastructure and projected through DomainEventRevisions. Use `listen` for reactions to state, not as a second event bus.
- **External IO**: retain meaningful Repository, NativeReader, ComicPageSource, Clipboard and sync/refresh contracts. Add a small Gateway only when it isolates actual IO.

Shared pure Dart collaboration signatures live in `shared/application/contracts/`; signatures requiring BuildContext live in `shared/ui/contracts/`. Tokens live in `shared/presentation/providers/`. A shared placement requires an unreachable owner, a public cycle, or a shared consumer; it cannot bypass a forbidden dependency.

## Product seams

Navigation uses AppNavigator and AppRoutes; go_router belongs to the routing host. `openReader` preserves its Future result. Shared ComicReadQuery supplies Reader metadata across the forbidden reader-to-comic edge. Series membership, reading context and ordering use shared contracts bound to series. Reading progress/activity capabilities stay with reading_history/reading_stats; shared progress consumers observe the existing shared stream.

Library commands preserve busy/backup guards, credential/root/settings ordering and core write exclusion. Metadata backup prepares a preview and manifest from the same payload, then commits after confirmation. Auto-backup execution/concurrency/success records belong to its use case; subscriptions, debounce and lifecycle cancellation remain in integration code, while file compression/retention belongs to the Gateway. Preserve partial commits: a later failure must not silently retry or compensate an earlier successful write.

Library form edit normalization belongs to the Library domain. Derive access and catalog kind from the saved Library, retain an Image set library's root, and normalize Image set libraries to Local-only access with no Comic format multi-select before validation or command selection (startup/interval scan settings remain editable). Draft flags cannot change these constraints. This keeps domain rules with their model ([Fowler](https://martinfowler.com/bliki/AnemicDomainModel.html)) and lets application orchestration depend on pure domain behavior ([Clean Architecture](https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html)).

Library deletion removes stored WebDAV credentials only after the core catalog deletion succeeds. A busy rejection or database failure preserves the credential and the original core error. Credential cleanup failures propagate after the catalog commit without retrying or compensating the deletion.

Remote Library registration is idempotent by normalized root and may return an existing Library. The returned identity does not prove that this invocation created it. If saving the password fails after core registration, preserve the committed catalog and propagate the original credential error and stack; do not delete the returned Library as compensation. Core registration failures do not invoke credential storage.

Library list projections belong to their request and UI lifetime. Older list responses and errors cannot replace a newer refresh or sidebar layout result. Accepted form and deletion commands retain the owner's result after disposal or replacement of the UI; presentation alone decides whether to refresh afterward. Initial loading can adopt an already accepted projection without repeating the load use case. Library loading includes migration writes, so provider failures remain visible until an explicit refresh or rebuild rather than automatically retrying that use case.

Each Library scan invocation owns its cancellation state and completion future. Cancelling updates presentation immediately, and restarting creates an independent run. Progress, errors and completion from an earlier run cannot change the current run or publish its success; repeated starts while the current run is running return the same future. The FRB adapter clears its active handle only when that handle still belongs to the finishing call.

Library initialization consumes typed migration checkpoints through its owner application contract. The infrastructure adapter maps resource-format and startup-scan migrations to the existing preference keys; composition injects it. LoadLibrariesUseCase shares only in-flight initialization preparation, registering it before calling injected dependencies. Both migrations and staged-payload cleanup run together once for overlapping loads; each caller then reads a fresh list and receives its own read error. Mark a checkpoint only after all corresponding writes succeed, retain partial successful writes, and clear staged input only when both migrations completed. Preparation is not permanently cached: a later explicit load retries incomplete checkpoints or failed cleanup using the retained source.

LibraryScanIntervalSchedule owns runtime Scan interval anchors in library_admin/domain. Reconcile Library snapshots to reset newly enabled/changed intervals, retain unchanged anchors and remove disabled/deleted entries. Bootstrap owns the Timer, startup frame/idle scheduling and sequential scan calls. After a scan call returns normally, advance the latest anchor by one period from the tick's Library snapshot, rather than resetting it to the current time. A thrown call does not advance its anchor. Keep these snapshot and completion semantics when settings change while a scan is queued.

Metadata backup preferences belong to the owner repository, injected by composition. Recording automatic backup completion writes directly to the repository captured when the use case is constructed, then invalidates the presentation projection only while its provider remains mounted; it must not construct a UI Notifier to persist success. Provider disposal does not cancel an accepted backup's completion record or replace its result with a UI refresh error. A failed preference write leaves the previously displayed completion intact and propagates to the existing coordinator error handler. A completed file write is not rolled back or automatically retried when recording completion fails.

The automatic backup coordinator waits for persisted scheduling preferences before passing enabled state and the previous completion time to the use case. Loading must not fall back to enabled with no previous backup. Pending frame callbacks and preference reads may start a backup only while the coordinator remains mounted; once accepted by the use case, file and completion writes retain their own lifecycle.

Metadata import preparation accepts selected bytes or reads the selected path through its file Gateway when bytes are absent. The same decoded payload supplies the manifest, preview and confirmed commit. Presentation owns file selection and confirmation dialogs; it does not open the file itself.

Tag dictionary network import uses ImportTagDictionaryUseCase to download through the existing Gateway and import the same bytes once through TagRepository. Rust retains parsing, filtering and deduplication. Download cancellation stays silent; repository failures, including cancellation exceptions, remain import errors with their original cause and stack. The ViewModel owns busy state, download cancellation/progress and refreshing the dictionary projection. Cancellation does not interrupt an import already started after download, and a failed projection refresh does not retry or compensate the committed import. Local byte imports need only the repository and UI refresh, without requiring the download Gateway.

Named metadata management owns its search snapshot and pinyin index in presentation. Successful add, rename, delete, merge and tag dictionary replacement invalidate both before refreshing the active query. Query changes reuse the current snapshot; they do not reload the whole dictionary on every keystroke. Write failures propagate without refreshing, and a refresh failure does not repeat the committed write.

Each metadata query refresh owns its query snapshot and response generation. Older refreshes, attachment-count queries and pagination responses cannot overwrite a newer query's items, counts, loading state or error. Search names and their pinyin index form one cache snapshot; dictionary invalidation prevents an earlier load from repopulating that cache. Disposed providers do not apply pending query results.

Comic's Smart facet match candidate query belongs to its application layer. It reads the owner dictionary before awaiting the setting, then uses domain ranking rules with Author path signals or ordered sibling Comic attachments. Disabled matching reads neither Library roots nor Series context or sibling Comics. Providers bind lazy queries and observe settings and Library state; they retain loading, errors and scope changes. One candidate query retains one Comic lookup repository snapshot; a fresh query resolves the dependency again. Preserve sequential sibling reads, missing-member handling and dictionary order rather than introducing a batch read, cache or retry while changing ownership.

Comic metadata editing uses two application operations: `ApplyComicMetadataFormUseCase` validates the domain diff, writes one Comic metadata patch and publishes `ComicMetadataPersisted` only after success; `SaveComicMetadataUseCase` then optionally persists Series ordering. Keep the first operation independently injectable for editor commands, preserve the existing write order and partial-commit behavior, and do not move event publication into presentation or domain.

Comic edit sessions derive Smart facet match scope from the current draft, immutable Comic identity/path and loaded Series membership. A late membership query cannot restore the opening title over an edited title. Comic and Series sessions only update presentation state while mounted after saving or changing field locks; disposal does not cancel the owner write, replace its result or trigger a retry.

Author detail rename commands target the stable Author ID. The owner repository and FRB command preserve that identity through to the core write, which retains the library write lock, name validation and commit notification. A stale display name is not a write key for a detail page; name-based management commands remain separate. Refresh the same Author detail only after a successful write and while its provider remains mounted.

Comic trash's application service owns purge-all target selection and post-purge reconciliation. It closes target sessions, executes the owner repository purge and, when any item succeeded, reads remaining trash to identify removed target IDs. Presentation keeps the busy precheck and cover-cache invalidation, consuming the outcome rather than querying trash again. Reconciliation failures propagate after the committed purge without retry or compensation; Rust retains resource deletion and transaction ownership.

Trash page refreshes merge fetched rows and counts with the latest selection, retaining the user's current selection mode and removing IDs no longer visible. A pending refresh cannot restore an earlier selection or erase a newer one. Selection gestures have a separate generation from data requests: an accepted restore or purge clears only the selection it started with. Disposal or rebuild prevents stale presentation updates without changing the owner command's result or retrying its write.

Trash refresh invalidates pending pagination and releases its obsolete loading indicator at the start. Pagination waits until the current refresh finishes so it cannot append an old page to a replaced first page. Only the matching refresh releases that reservation; old pagination errors do not log or clear a newer request's loading state. A refresh failure retains displayed rows and allows a subsequent page request.

App update checks run through CheckAppUpdateUseCase: each invocation fetches a fresh stable release, compares versions and optionally reads the latest dismissed version after the response. Manual checks bypass dismissal; dismissed releases stay silent, distinct from an installed version that is already current. The controller supplies the installed version and owns startup scheduling, dialogs, feedback and exception presentation. Gateway failures propagate from the use case without retry.

SettingsNotifier serializes accepted whole-setting snapshots in request order while retaining optimistic UI updates. A failed older request cannot overwrite a newer request's presentation. Ordinary setting failures restore the most recent successful snapshot when the request started with data; Reader and sidebar setters retain their existing error-state presentation. Reserve each request's completion before notifying listeners, and let accepted writes finish after disposal without reading Ref or updating disposed state. Do not merge, drop or retry requests.

Reader's ManageReadSessionUseCase serializes progress writes in request order, registering each tail before invoking the injected command. Each caller receives its own failure; a failed predecessor does not skip later writes or retry a possibly committed save. Queued writes read the captured session's latest page and the clock when execution begins. Begin/end transitions retain their own session references, and only the latest transition may install a new active session, including when an intervening transition exits or enters incognito mode. Already started writes and activity reports retain their existing completion and error semantics.

OpenReadSessionUseCase owns each Read session source's open lifetime (keyed by `sessionKey`) and shares pending page-list preparation within it. Closing or timing out invalidates that lifetime, preventing late lookup, native open, page-list or resume results from restoring its cache or returning an obsolete session. Native Comic operations and cleanup for the same Comic remain ordered: a new open waits for an uncancellable previous native operation and its cleanup, while its caller retains a bounded open timeout. Different session keys remain independent. Closing reports its own native error; cleanup of a failed open must not replace that open's failure. Resume options remain specific to each caller. Image set opens use `ImageSetReadPort` and do not open a native Comic session.

Image set thumbnail entry retains the selected Image set image identity through Reader's source contract. OpenReadSessionUseCase resolves that identity separately for each caller against the opened page snapshot, including shared/cached opens. An obsolete catalog index must not prevent loading that snapshot or select another image after sync reordering. If the selected image is absent, opening reports resource-not-found; index-only callers retain their existing behavior. No extra catalog query or Comic history write is introduced. Presentation and application consume `ReadSessionCapabilities` for progress, Series navigation, cover actions, native prefetch and exit policy rather than catalog-kind branches (ADR-0061).

Rust's session store owns native acquire lifetimes and reference counts. Core open and ephemeral-read entries capture their Comic's lifetime before database/access checks or backend I/O; overlapping acquires share it. Close invalidates it even before a session is published, and clearing sessions invalidates all pending lifetimes in the same store lock. Acquires validate before cache reuse and after backend I/O. An obsolete successful backend open returns ReaderSessionNotOpen; backend failures retain their original error. Ordinary reference release preserves another pending acquire in that lifetime. Each registered backend has a distinct instance identity, even when inserted again within the same open lifetime. An ephemeral lease releases only the exact acquired instance, including during callback unwinding, so an old callback cannot decrement a replacement session. Explicit close still force-removes the session. These rules do not establish ordering before entry into core.

Native page lists, page bytes and cached-page reads consume an opaque session snapshot containing the acquired backend instance, path and resource type. Core APIs derive source path and resource type from that snapshot rather than independent caller arguments. Backend access verifies its exact instance under the session-store lock; close/reopen or ordinary release followed by backend replacement cannot make an old read use the new backend. Ephemeral callbacks receive the snapshot returned by their own acquire. FRB captures read snapshots before blocking dispatch, using compensated blocking on its native multithread Tokio runtime while waiting for the session lock. Session and cache snapshots are captured sequentially without nesting their locks. The snapshot guards backend access and retains the source metadata version; it does not cancel already decoded bytes. The existing best-effort page-list metadata writeback remains a later operation; this read identity check does not cancel already accepted persistence work.

Reader disk-cache keys belong to the source metadata captured while opening the backend, using ResourceAccess rather than filesystem metadata read later from a path. File metadata must match before and after opening; failures propagate without retry. ResourceAccess exposes a local path only for mutable filesystem sources, while other adapters provide owned stream snapshots. Local file reads validate kind, modification time and size before and after decoding, including path-bound RAR/7z/PDF; a changed source requires reopening. These metadata checks run outside the global session-store lock, and backend access checks the instance again under the existing decode lock. Directory page-list snapshots retain their existing behavior. Unknown modification times bypass persistent cache setup, lookup and publication in foreground and byte reads, and prefetch stays a no-op. The v2 cache namespace ignores potentially misidentified legacy entries without deleting them. Versions use modification time and size rather than a content hash, so changes that preserve or restore the same metadata cannot be detected.

Reader prefetch presentation assigns generations that remain distinct across clear and reopen. After awaiting dispatch, only the current mounted window may invalidate touched page providers or cached path bytes, and an obsolete warm operation returns false so its caller skips precaching. Provider rebuild clears window and touched-page snapshots. Identical windows still reuse their work and different Comics remain independent. This guards Dart continuations; FRB prefetch dispatch does not wait for the native background task to finish.

Native Reader prefetch and cache clear reserve an opaque request identity at the Rust API entry before dispatching blocking work. Worker start order and repeated client generation values cannot replace the latest accepted request. The Reader cache module owns each Comic's mutation gate: cached-page lookup, page publication, prefetch eviction and clear validate ownership while holding that gate. Session lookup and page decoding stay outside it; decoded bytes are checked again before publication. A delayed clear skips a newer prefetch window, and obsolete decoding cannot refill a cleared cache. Prefetch page failures remain best-effort; current eviction and clear failures retain their errors. This does not establish call order before the Rust API entry or pin a returned file against a later clear or eviction.

Foreground page loads capture a separate cache lifetime before blocking dispatch. Prefetch window changes do not invalidate it. Reserving a clear invalidates older reads and marks clearing pending; foreground reads captured during that pending interval skip cache lookup and publication until the clear finishes or a newer prefetch supersedes it. An obsolete clear cannot release a newer clear's barrier, and a current failed clear releases its own barrier before returning the error. A foreground load still requires an open native session, retains lookup/decode errors and returns its unmodified source bytes when cache publication fails or is no longer allowed. Directory page paths retain their existing direct-file behavior.

Reader owns selected-page source bytes consumed by Comic/Series cover commands and Author images. Its byte-loading entry acquires and releases an ephemeral session while preserving an existing Reader session. Cached archive lookup and the complete byte copy share one cache gate, so consumers receive owned bytes rather than reopening a temporary Reader file path. Cache misses decode outside the gate, attempt the existing best-effort cache write and return the same bytes without reopening the written file. Directory reads share Reader's page order, index validation and page-list writeback. Cache lookup/read and source decode failures propagate; encoding and cover persistence remain with their existing owners.

Reading history's paged feed owns query generations across provider rebuilds, silent refreshes and pagination. A keyword change or disposal invalidates pending responses, errors and refresh cleanup from the previous generation. Page results retain the keyword captured when queried; an older refresh must not relabel its rows with the current keyword or end a newer request's loading state. History change subscriptions and debounce timers remain presentation lifecycle concerns.

History delete and clear commands retain their owner write result after disposal or a query change, without modifying the replacement query's presentation. Query lifetime is distinct from fetch generation: a same-query refresh does not cancel an accepted command's local completion. Successful local completion invalidates older reads, releases their refresh and pagination loading state, and preserves pending revision reconciliation; a failed write leaves those reads valid. If the query's first page is still loading, rebuild that query after the write so its old build cannot restore deleted rows. Deleting an item already absent from the displayed page does not decrement its count again. Neither lifecycle changes nor projection reconciliation retry a write.

Reader fullscreen state belongs to ReaderChromeNotifier; the owner command injects the window effect. Entering hides application chrome before awaiting the native resize; exiting restores chrome only after the native call succeeds. Native errors propagate with chrome still hidden, without retry or compensation. Composition selects desktop window effects and a no-op on other platforms; the same in-app fullscreen state remains available everywhere.

Reader cover editing consumes shared Comic and Series cover commands, with no direct dependency on either owner's repository or cache. Composition binds the Comic command that writes the selected page, reads the resulting thumbnail and updates its cache only for non-empty bytes. The Series command waits for its cover write before invalidating the Series cover projection through the existing slot. Later read or invalidation failures propagate without repeating or compensating the committed write.

Domain facts and event interfaces have one source in `shared/domain/events/`. The implementation is `infrastructure/events/StreamDomainEventBus`; providers are adapters, not event publishers in presentation.
